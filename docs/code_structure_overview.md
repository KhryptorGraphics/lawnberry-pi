|`backend/src/services/robohat_service.py`|Serial bridge to RoboHAT RP2040; translates high‑level control into the firmware’s text protocol; maintains health status. Drive commands carry a validity window (`ROBOHAT_COMMAND_VALIDITY_S`, default 0.5 s, max 10 s): only a fresh command is refreshed, expiry sends neutral once and leaves the firmware failsafe in charge (no blind resend). A software E-stop holds neutral and refuses drive/blade-on until cleared; `park()` is used on shutdown. The E-stop hold is re-checked after the RC→USB handshake and again immediately before the write, so a command that was waiting for the handshake can no longer land after a stop (audit SF-02); the hold keeps USB control and the constant neutral alive by itself (SF-10); a command with a shorter validity window wakes the expiry task so it re-arms (SF-07); NaN/inf wheel speeds or PWM values are refused with `last_error=non_finite_command` (SF-12); `park()` latches until `initialize()` (only neutral drive and blade-off are accepted), so a loop still running during shutdown cannot re-command the platform (SF-06).
